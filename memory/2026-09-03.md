## 16:00-16:30 — 关键发现: v31 binary decode function layout bug

### 现象
- service log 显示 `dets=3120/count=301 ≈ 10 box/帧` → 模型在跑，输出 10 个 box
- 但 RTSP overlay 只画 1 个 box (person 54% 在右下角小框)
- 不是我之前误判的"yolov8s_scene_ft_v2 auto_label bug"，而是**v31 binary 的 yolov5_decode_all 函数 layout 错**

### 根因
- NPU output dim: `85 80 80 3` (C, H, W, A) — 实际 layout 是 (A, H, W, C)，anchors 在最外
- v31 binary `yolov5_decode_all` 假设 NHWC (H, W, A, C):
  ```cpp
  int idx = (gy * gs + gx) * YOLO_NUM_ANCHORS * 85 + a * 85;
  ```
- 错误 layout 公式 (anchors 在 (gy, gx) 之内而不是之外)
- 导致 obj/conf score 错位读，1-2 个 anchor 碰巧突破阈值，NMS 只剩 1 个 box
- 8-7 笔记 size0 = `1*3*80*80*85` (anchors outer) 是关键证据

### 修复 (板端编译)
```cpp
// 改前:
int idx = (gy * gs + gx) * YOLO_NUM_ANCHORS * 85 + a * 85;

// 改后 (layout (A, H, W, C), anchors outer):
int idx = (a * gs * gs + gy * gs + gx) * 85;
```
- 编译命令 (板端 aarch64):
  ```bash
  g++ -O2 -std=c++17 -o v31_v4l2_od_rtsp.new v31_v4l2_od_rtsp.cpp \
    $(pkg-config --cflags gstreamer-1.0 gstreamer-rtsp-server-1.0 gstreamer-app-1.0) \
    $(pkg-config --libs gstreamer-1.0 gstreamer-rtsp-server-1.0 gstreamer-app-1.0) \
    -I/usr/include/opencv4 \
    -lopencv_core -lopencv_imgproc -lopencv_imgcodecs \
    -ldl -lpthread
  ```
- 部署: `sudo cp v31_v4l2_od_rtsp.new /home/radxa/v31_v4l2_od_rtsp`
- 备份: `.bak_decode_fix_20260903_155527` (旧 binary c2a24c79) + `.bak_decode_fix2_20260903_155638`

## 23:30-00:30 — Windows VLC 拉流 + 80 类 person/cat/dog 抖动根因分析

### VLC 拉流 (Windows)
- 老板用 `vlc rtsp://192.168.2.5:8554/test --rtsp-tcp --network-caching=3000` 在 Windows 上拉流
- 首次黑屏 → Windows 防火墙拦截 → 允许后正常拉流
- service log 显示 `client=1` + 推流 buffer 计数

### 观察到的现象 (老板实测)
- 完整脸: person 40-60%, cat 20-40%, 偶尔 dog
- **遮住下半脸** (用手或物体遮嘴/鼻/下巴): person 0%, **cat 100%**
- 这是决定性实验数据

### 严格 5 层 RCA
1. **表象**: top1 class 每帧切换
2. **直接原因**: person/cat/dog conf score 接近，都 > 0.20
3. **层级 3 - 模型特征层 (根因 A)**: COCO 训练分布
   - person 类 262K 标注，close-up face < 30K (12%)
   - cat/dog 类 close-up face 占比反而高
   - COCO benchmark: person AP=0.72, cat AP=0.722, dog AP=0.71 (模型本身学得就分不开)
4. **层级 4 - 单帧推理层 (根因 B)**: 无时序约束
   - 模型无 RNN/attention over time
   - 单帧 conf 接近 + NMS noise → top1 抖动
5. **层级 5 - 推理参数层 (次要)**: conf 阈值 + blacklist

### 老板实验数据排除其他嫌疑
- ❌ 不是 NMS noise (同一帧内 conf 跨类跳变不能用 noise 解释)
- ❌ 不是时序问题 (帧间跳动是 conf 接近的结果，不是原因)
- ❌ 不是 conf 阈值太低 (阈值再高，person/cat conf 仍接近)
- ❌ 不是 binary bug (decode fix 后位置已对)

### 理论链
```
COCO person 类 12% close-up face 样本
  ↓
模型学到的 person 特征 ≠ close-up face 全貌特征
  ↓
"上半脸 + 双眼 + 眼镜" 命中 cat 类 close-up face 高
  ↓
yolov5s 浅层 cell=8×8px, 深层=32×32px
  ↓
1 张脸只占 1-2 个深层 cell → 区分度不足
  ↓
person/cat/dog 三类 conf 全部 ≥ 0.20 → top1 抖动
```

### 修法 (按 ROI 排序)
| # | 修法 | 工作量 | 根治率 |
|---|---|---|---|
| ~~fine-tune 你场景~~ | ~~半天~~ | ❌ **单点解, catastrophic forgetting 破坏 80 类** |
| Z (temporal voting) | 30 min | 50% (修帧间跳, 但遮脸仍 fail) |
| X (换 yolov8s 80 类) | 半天 | 60-70% (更好的 close-up 区分度) |
| Y (提分辨率 1280) | 半天 | 60% (FPS 14 → 7) |

### 老板的 deep insight
"fine-tune 你场景是不是只能解决单点问题" — **是的**:
1. catastrophic forgetting → 80 类能力下降
2. 换人/换场景就坏
3. 每次场景变要重训
- 老板立即识别到 fine-tune 不适合产品化场景（80 类通用检测诉求）
- 推荐方案改为 **X + Z 组合**: 30 min 上 Z (立即解决帧间跳), 半天上 X (长期方案)
